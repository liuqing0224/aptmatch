## 1. 项目概览

AptMatch 是一个**面向求职者的本地 Web 应用**：把「某份简历 × 某家公司/岗位的契合度分析」作为任务，派发给**本机 coding agent**（codex 默认，可切 cursor / claude）。agent 默认联网调研公司，返回结构化评分报告。

- 架构灵感：参考 [Multica](https://github.com/multica-ai/multica) —— 让本地编码 agent 像队友一样接任务、自主执行、回报结构化结果。
- 运行形态：**仅监听 127.0.0.1、单用户、无鉴权**，数据全部落在本机 `.data/`。
- 技术栈：**npm workspaces**（server + web）；后端 Express + better-sqlite3；前端 Vite + React + TS。

一句话定位：**前端看板 → 后端调度 → 本地 coding agent CLI → 注入的 Markdown 提示词**，整个系统没有中心化的 Agent 编排服务，调度本质是「SQLite 状态机 + 定时 tick + 子进程派生」。

## 3. 后端结构（server/，30 文件：29 .js + 1 .json）

### 3.1 入口与框架

- **入口**：`server/index.js` —— `createApp()` 工厂；直接运行时 `app.listen(8787, 127.0.0.1)`。
- **框架**：Express 4，无独立中间件栈，错误处理用最后的 `(err,req,res,next)=>{...}`。
- **生产托管**：若 `web/dist` 存在则 `express.static` 托管，并对非 `/api` 的 GET 回退 `index.html`（SPA）。

### 3.2 路由组织（全部挂在 `/api/*`）

`server/index.js` 中挂载 8 个 Router：

| 路由前缀 | 文件 | 职责 |
|---|---|---|
| `/api/health` | index.js 内联 | 健康检查 `{ok,time}` |
| `/api/agents` | `routes/agents.js` | agent 增删改查 + 档案/技能读写 |
| `/api/resumes` | `routes/resumes.js` | 简历上传(multer)/列表/删除，调 `extract.js` 解析 PDF/DOCX |
| `/api/companies` | `routes/companies.js` | 公司/JD 上传/列表/删除 |
| `/api/tasks` | `routes/tasks.js` | 任务创建/列表/详情/取消/重跑/追问/日志 |
| `/api/matches` | `routes/matches.js` | 已完成契合度任务的横向对比数据 |
| `/api/settings` | `routes/settings.js` | 设置读写 + `/providers` 扫描本机 CLI |
| `/api/crawl` | `routes/crawl.js` | 创建采集任务 + 导入结果并批量派发 |
| `/api/blacklist` | `routes/blacklist.js` | 黑名单检索/校验/同步/来源管理 |

### 3.3 核心 lib 模块职责

| 模块 | 职责 |
|---|---|
| `db.js` | 打开 SQLite(better-sqlite3)，WAL 模式；`migrate()` 建表；`nowIso()`/`rowById()` |
| `lib/paths.js` | 全部路径常量：`DATA_DIR(.data)`、`AGENTS_DIR(agents)`、`JOBS_DIR(.data/jobs)`、`UPLOADS_DIR`、`LOGS_DIR`、`DIST_DIR` |
| `lib/queue.js` | **调度队列**：`setInterval(tick,1000)`；按并发取最早 `queued` → `running` 并调 `runner.run()`；`recoverRunningTasks()` 启动时把 `running` 改回 `queued` |
| `lib/runner.js` | **任务执行核心**：建工作区→写 input/prompt/AGENTS.md/skills→`spawn` provider CLI(detached)→轮询 `output/report.json`/`crawl_results.json`→`validate`→`finish()`；含 `RUNNER=mock` 模拟分支；`cancel()`/`killGroup()` |
| `lib/providers.js` | **Provider 适配**：`scanProviders()` 扫 PATH+常见目录检测 codex/cursor/claude；`buildCommand()` 拼 CLI 参数 |
| `lib/validate.js` | **报告契约**：`DIMENSION_KEYS`(10 维)、`GRADES`(S/A/B/C/D)、`DIMENSION_WEIGHTS`(和=100)；`validateReport`/`validateCrawlResults` |
| `lib/agentfs.js` | **agent 文件系统**：读写 `agents/<slug>/AGENTS.md`、`skills/*.md`；`appendLearnings()` 把报告 learnings 追加到 `skills/learnings.md` |
| `lib/settings.js` | 设置读写；启动即 `detectDefaultProvider()` 探测默认 provider |
| `lib/extract.js` | 用 `unpdf`(PDF)/`mammoth`(DOCX)/utf8 提取简历/JD 文本 |
| `lib/crawl.js` | **采集员角色**：`CRAWL_AGENTS_MD`(内置采集员提示词)、`parseCrawlParams()`、`buildCrawlPrompt()` |
| `lib/blacklist.js` | 解析 GitHub 仓库 md 黑名单表格；`gh CLI`→匿名 HTTP 兜底；模糊匹配 `checkCompany()`；幂等 upsert |
| `seed/default-agent.js` | 默认 agent「契合度分析师」档案 `PROFILE_MD` + 5 个技能 `SKILLS`；首次启动写入库与磁盘 |

### 3.4 数据模型（SQLite，`db.js` 迁移）

`agents` / `resumes` / `companies` / `tasks` / `settings` / `blacklist_sources` / `blacklist_entries`。

关键：`tasks` 表含 `mode`(`fit`/`research`/`crawl`/`followup`)、`status`(`queued`/`running`/`done`/`failed`/`cancelled`)、`agent_id`/`resume_id`/`company_id`/`parent_task_id`、`result`(JSON 文本)、`pid`、`started_at`/`finished_at`。`tasks` 与 `agents/resumes/companies` 仅为逻辑外键（删除时置 NULL，不级联）。

### 3.5 模块依赖关系

```
index.js（装配中心）
 ├─ db.js
 ├─ lib/settings.js ── lib/providers.js(detectDefaultProvider)
 ├─ lib/runner.js（TaskRunner）
 │    ├─ lib/providers.js (buildCommand)
 │    ├─ lib/validate.js (validateReport)
 │    ├─ lib/agentfs.js (readAgentProfile, appendLearnings)
 │    ├─ lib/crawl.js (CRAWL_AGENTS_MD)
 │    └─ db.js
 ├─ lib/queue.js (createQueue) ── runner.run / getSettings
 └─ routes/*.js（注入 db / runner / queue）
```

**依赖走向清晰**：`index.js` 是装配中心；`queue → runner → providers/validate/agentfs` 是执行主链；`routes` 只负责 HTTP 边界与 DB 读写，重逻辑都在 `lib/`。

## 5. agents/ 目录（8 个 .md）—— 是提示词/角色定义，不是代码

这些 Markdown **正是注入给本地 coding agent 的角色档案与技能沉淀**：

- `agents/analyst/AGENTS.md`：默认 agent「契合度分析师」系统提示词——工作流、评分准则、**十维权重表(总和 100)**、输出 schema(`output/report.json`)。内容与 `seed/default-agent.js` 的 `PROFILE_MD` 一致（首次启动写入磁盘）。
- `agents/analyst/skills/*.md`（5 个）：`resume-parsing` / `jd-analysis` / `company-research` / `fit-scoring` / `interview-questions`，可复用启发式。
- `agents/analyst/skills/learnings.md`：任务完成后由 `agentfs.appendLearnings()` 自动追加「规律」，下次任务随 `skills/` 注入。
- `agents/x/skills/learnings.md`：一个空壳 agent「x」（仅 learnings），属示例/残留。

**与调度的关键闭环**：`runner.run()` 读取 `agents/<slug>/AGENTS.md` 写入任务工作区，并把 `skills/*.md` 复制进去。Agent 管理页（`routes/agents.js` → `agentfs`）对文件的编辑**直接在下一次任务生效** —— 即前端编辑的就是真实提示词。`crawl` 模式不走 `analyst/AGENTS.md`，而是用 `lib/crawl.js` 内置的 `CRAWL_AGENTS_MD`。

## 7. 核心流程

### 7.1 主链路 A：单个契合度分析（fit）

```
[web NewMatch] 选 resume+company+agent+mode/extra_prompt
   │ POST /api/tasks  {resume_id, company_id, agent_id, mode}
   ▼
[tasksRouter] 校验 → INSERT tasks(status=queued) → queue.enqueue()
   ▼
[queue.tick] 取最早 queued → UPDATE running → runner.run(task)
   ▼
[runner.run]
   ├─ 建 .data/jobs/<id>/{input,output}
   ├─ 写 input/resume.md jd.md company.md、prompt.txt
   ├─ 写 AGENTS.md(=agents/<slug>/AGENTS.md) 与 skills/(复制)
   └─ spawn provider CLI(detached, e.g. codex exec … -C <workspace> "<prompt>")
   ▼
[本地 coding agent] 读 input/*、遵守 AGENTS.md、联网调研公司
   └─ 写 output/report.json
   ▼
[runner 轮询] 读到 report.json → validate.validateReport()
   ├─ 通过 → finish(done) + appendLearnings 到 skills/learnings.md
   └─ 失败 → finish(failed, "schema校验失败")
   ▼
[web Board/Report 轮询]
   ├─ 渲染雷达图+十维+差距+面试题+调研来源
   ├─ 调 /api/blacklist/check 命中则显示求职警示条
   └─ 可「追问」(POST /api/tasks/:id/followup → 新 followup 任务)
```

### 7.2 主链路 B：批量爬取并匹配（crawl → import）

```
[web NewMatch(crawl tab)] 填 关键词/城市/数量(+可选简历)
   │ POST /api/crawl  {keyword, city, limit, resume_id, agent_id}
   ▼
[crawlRouter] INSERT tasks(mode=crawl) → enqueue
   ▼
[runner.run] 注入 CRAWL_AGENTS_MD + input/task.md + prompt.txt
   ▼
[agent] 从 BOSS直聘/官网抓取真实 JD → 写 output/crawl_results.json
   ▼
[runner] validateCrawlResults → done
   ▼
[web Report 渲染 CrawlResultsView] 勾选结果 + 选简历/agent
   │ POST /api/crawl/:taskId/import {indices, auto_dispatch:true}
   ▼
[crawlRouter.import] 每条→INSERT companies；若 auto_dispatch→INSERT tasks(mode=fit) → queue.enqueue()
   ── 回到 链路 A
```

### 7.3 关键机制小结（引用 README「工作原理」）

- **调度**：每任务独立工作区 `.data/jobs/<taskId>/`，agent 必须把报告写入 `output/report.json`。
- **Provider 适配**：扫描 PATH 检测 codex→cursor→claude 首个可用者为默认；模型可在 agent 档案配置。
- **报告契约**：`validate.js` 严格校验（总分 0-100、S/A/B/C/D、十维且权重和=100、差距/面试题/来源齐备），非法判失败。
- **技能沉淀**：`report.learnings` 自动追加 `skills/learnings.md`，后续任务注入。
- **重启恢复**：`running`→`queued` 重新入队（`recoverRunningTasks`）。
- **数据本地**：SQLite `.data/app.db` + 上传/工作区/日志全在本机。
- **黑名单**：从 GitHub 社区仓库拉 md 表格（gh CLI 优先，失败回退匿名 API），幂等 upsert，同步失败不阻塞主流程；报告页按公司名模糊匹配显示警示。

## 9. 总结

**结构**：`web`(React/Vite 看板) → `server`(Express + SQLite，含 queue/runner/providers/validate 四件套) → 本地 coding agent(codex/cursor/claude CLI) → `agents/`(注入的 Markdown 角色与技能)；`scripts/smoke.mjs` 验证全链路。

**流程**：前端派发任务入 SQLite 队 → 队列按并发拉起 → runner 为任务建隔离工作区并注入 `AGENTS.md`+skills，派生本地 agent CLI 联网产出 `report.json` → 后端校验落库 → 前端轮询渲染十维雷达报告，并可追问/对比/导入黑名单警示。

**设计要点**：整个系统无中心化 Agent 编排服务，调度就是「SQLite 状态机 + 定时 tick + 子进程派生」，agent 的「智能」完全来自 `agents/*.md` 提示词与本地 CLI。数据全本地、仅本机监听、无鉴权——典型单机生产力工具形态。
