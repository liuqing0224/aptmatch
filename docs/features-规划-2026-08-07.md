# 功能规划：面试闭环 / 对比增强 / 批量预筛

> 分支：`feature/interview-loop-compare-prescreen`（基于 master）
> 规划日期：2026-08-07
> 基线：当前仓库 master @ `46bcc21`，未安装 node_modules（`npm install` 后以 `npm test` 校验）

---

## 0. 三个功能一句话

1. **面试准备闭环**：报告里已有「面试题」，把多次 followup 串成一条**模拟面试对话流**（agent 扮演面试官逐轮提问、点评回答、给提示），而不是每次孤立追问后看一张新报告。
2. **对比增强**：在已有「十维横向对比」表之上，新增**同公司历史趋势**（分数随时间变化折线）、**差距热力图**（公司 × 维度配色块）、**报告导出 PDF**（单报告 + 对比表）。
3. **批量结果智能预筛**：crawl 后仍是人工勾选，新增按**薪资区间 / 城市 / 匹配分**的预筛工具栏与「全选通过预筛」，减少人工。

共同点：不新增第三方前端图表库（沿用 RadarChart 的手写 SVG 风格）、不改 `tasks` 表结构（`mode` 是自由 TEXT）、尽量复用现有 queue/runner/轮询机制。

## 1. 功能一：面试准备闭环（模拟面试对话流）

### 1.1 现状

- fit 报告含 `questions: [{question, why}]`。
- followup 走 `POST /api/tasks/:id/followup` → 新建 `mode='followup'` 任务 → runner 写 `input/previous_report.json` → agent 重新产出**整份 fit 报告** → 前端新开一页。
- 本质是「一次性追问」，无对话上下文、无回合概念、不点评候选人回答。

### 1.2 目标交互

在报告页点「开始模拟面试」→ 进入对话流视图：

```
[面试官] 第 1 轮：请先自我介绍，并结合你简历中的 XX 项目谈谈…（基于报告 questions/gaps）
[候选人] 输入回答 → 提交
[面试官] 点评 + 提示 + 第 2 轮问题
[候选人] …
…… 直到 agent 判定结束（或用户点「结束」）→ 展示整体评估
```

- 每轮一个任务（`mode='interview'`），通过 `parent_task_id` 串成链；**无需新表**。
- 候选人的回答存 `extra_prompt`（JSON），agent 输出到 `output/report.json`（interview schema）。
- 对话流视图轮询当前轮任务状态，像聊天一样实时刷新。

### 1.3 契约设计

新任务模式 `mode='interview'`。每轮 `report.json` 使用新 schema（新增 `validateInterviewTurn`）：

```json
{
  "schema_version": 1,
  "type": "interview_turn",
  "round": 1,
  "question": "本轮面试官提问（首轮为开场题）",
  "evaluation": "对候选人上一轮回答的点评（首轮为空串）",
  "hint": "候选人下一轮答题要点提示（可为空）",
  "finished": false,
  "overall_assessment": "结束时整体评估与建议（未结束时为空串）",
  "learnings": []
}
```

`extra_prompt`（每轮任务的输入，JSON）：

```json
{ "round": 1, "answer": "候选人上一轮的回答", "max_rounds": 8 }
```

根 interview 任务（round 1）的 `answer` 为空；用户提交回答后由后端派生下一个任务 `round = round+1`。

### 1.4 后端改动

| 文件 | 改动 |
|---|---|
| `server/lib/validate.js` | 新增 `INTERVIEW_GRADES`/`validateInterviewTurn()`：校验 round 正整数、question 非空、finished 布尔、finished=true 时 overall_assessment 非空；`sanitizeInterview()` |
| `server/lib/interview.js`（新） | `INTERVIEW_AGENTS_MD`（面试官角色提示词：逐轮提问→点评→提示→最多 max_rounds 轮→总结）、`parseInterviewParams()`、`buildInterviewPrompt()` |
| `server/lib/runner.js` | `writeInputs()`：interview 模式沿用 fit 的输入写法（resume/jd/company/AGENTS.md），额外写 `input/previous_report.json`（父报告）与 `input/interview_history.md`（**沿 parent_task_id 链回溯、汇总此前所有轮次的 question/answer/evaluation**，供 agent 保持上下文）；`buildPrompt()` 增加 interview 分支；`OUTPUT_FILE` 对 interview 仍是 `output/report.json`；runProvider 校验分支 `validateInterviewTurn`；`runMock` 增加 interview 模拟 |
| `server/routes/tasks.js` | 新增三接口（见下） |

接口：

```
POST /api/tasks/:id/mock-interview/start   body {max_rounds?}
   从已完成 fit 任务派生出 round=1 的 interview 任务（继承 agent/resume/company/parent=该 fit 任务）
POST /api/tasks/:id/mock-interview/answer  body {answer}
   校验 task.mode=='interview' 且为最新一轮（其自身已 done）；新建 round+1 的 interview 任务
GET  /api/tasks/:id/mock-interview
   返回整条对话链：{turns:[{round, question, answer, evaluation, hint, finished, overall_assessment, status, created_at}], fit_report}
```

- `serialize()` 对 interview 任务照常返回 result（前端读 `result.type==='interview_turn'` 区分）。
- **注意**：`GET /api/matches` 与 Compare 页会把 interview 任务误当成 fit 报告。matches.js 的 SQL 需排除 `mode IN ('crawl','interview')`（改现有 `mode != 'crawl'` → `mode NOT IN ('crawl','interview')`）。

### 1.5 前端改动

| 文件 | 改动 |
|---|---|
| `web/src/types.ts` | 新增 `InterviewTurnReport`、`MockInterviewChain`、`Task.mode` 补 `'interview'` |

| `web/src/components/MockInterview.tsx`（新） | 对话流 UI：轮次气泡、回答输入框、轮询最新轮状态、开始/回答/结束按钮、链式回显（从 `GET mock-interview` 拉全链） |
| `web/src/pages/Report.tsx` | 报告页面试题卡片旁加「开始模拟面试」按钮；`task.mode==='interview'` 时渲染 `<MockInterview/>` 替代 fit 报告展示；隐藏「继续追问」卡片 |

### 1.6 测试

## 2. 功能二：对比增强

### 2.1 同公司历史趋势

**目标**：同一家公司（同 resume）多次匹配/重跑后，看整体分与各维度随 `created_at` 的走势。

- 后端 `server/routes/matches.js` 新增 `GET /api/matches/trend?company_id=X&resume_id=Y`：返回该公司全部 done 任务（按时间升序）`[{task_id, created_at, overall_score, grade, dims:{key:score}}]`；无历史时 `{trend:[]}`。
- 前端 `web/src/components/TrendChart.tsx`（新，手写 SVG 折线，风格仿 RadarChart）：X=时间、Y=总分；点击 Compare 表格的公司行 → 展开/弹出趋势面板，并支持勾选维度看单维折线。
- `web/src/api.ts` 新增 `matches.trend()`；`web/src/pages/Compare.tsx` 公司列加「趋势」入口。

### 2.2 差距热力图

**目标**：把「公司 × 十维」的横向对比做成配色块热力图，一眼看出哪些公司哪几维是短板。

- 纯前端实现：Compare 页新增「表格 / 热力图」切换。热力图 = 公司行 × 维度列，单元格按分数填色（高=绿、中=黄、低=红，沿用现有 `ok/mid/low` 语义 + 背景色），悬停显示 reason。
- 数据源不变（`matches` 已含 dims）。`web/src/components/CompareHeatmap.tsx`（新）。
- 可加「平均分行」辅助解读。

### 2.3 报告导出 PDF

**目标**：报告导出不再只有 Markdown，增加 PDF。

- 后端 `server/lib/pdf.js`（新）：用已存在的 `pdfkit`（**注意：当前在 server 的 devDependencies，需移到 dependencies**）生成 PDF。
  - `buildFitReportPdf(task, report)`：总分/等级 + 十维列表 + 差距/面试题/建议/来源，内容对齐现有 `exportMarkdown`。
  - `buildComparePdf(rows, dimKeys)`：对比表导出。
  - **中文渲染**：pdfkit 内置字体不含 CJK，需注册系统字体。规划用 `findCjkFont()` 探测常见系统路径（macOS `PingFang.ttc`/`Hiragino`、Windows `msyh.ttc`、Linux `Noto Sans CJK`），找不到则退化为仅英文/提示；macOS 为本项目主运行环境，优先 PingFang。
- 路由：
  - `GET /api/tasks/:id/export.pdf`（tasks.js）→ `Content-Type: application/pdf` + 附件下载。
  - `GET /api/matches/export.pdf?resume_id=`（matches.js）→ 对比表 PDF。
- 前端：Report.tsx「导出 Markdown」旁加「导出 PDF」（`window.open('/api/tasks/xxx/export.pdf')` 或 fetch blob 下载）；Compare.tsx 顶部加「导出 PDF」。
- `server/test/pdf.test.js`（新）：以 fit 报告与 mock 对比数据渲染，断言产出 PDF 头 `%PDF-` 且非空。

## 3. 功能三：批量结果智能预筛

### 3.1 现状

`CrawlResultsView` 逐条人工勾选，每条只有 salary/location 等原文；`salary` 是 "25-50K" 这类字符串，无法按区间过滤。

### 3.2 目标交互

crawl 完成页顶部加「预筛」工具栏：

```
[最低薪资 K] [最高薪资 K] [城市/地区] [最低匹配分 0-100]  [应用预筛] [清除]
[全选通过预筛]   ← 一键只勾选满足条件的条目
```

每条结果追加展示「匹配分 xx」「解析薪资 25-50K」标签；筛选条件实时作用于勾选集合。

### 3.3 实现

- `server/lib/prescreen.js`（新，纯函数，便于单测）：
  - `parseSalaryK(salaryStr)`：解析 `"25-50K"` / `"20-30K·13薪"` / `"25K以上"` / `"面议"` 等 → `{minK, maxK, raw}`；无法解析返回 null。
  - `cityMatch(location, query)`：城市/地区模糊包含。
  - `scoreMatch(resumeText, jdText)`：简历与 JD 的关键词重合度 0-100（简单分词 + 停用词 + 高频词交集比例，启发式即可，不调用 agent）。
- 路由 `server/routes/crawl.js` 新增 `POST /api/crawl/:taskId/prescreen`，body `{resume_id, filters:{minK,maxK,city,minScore}}`：
  - 返回 `{results:[{index, salary:{minK,maxK,raw}, score, city_ok, salary_ok, score_ok, passed}]}`；`passed = salary_ok && city_ok && score_ok`。
  - 无 resume_id 时 `score` 与 `score_ok` 跳过（`minScore` 忽略）。
- 前端 `CrawlResultsView.tsx`：顶部加预筛工具栏与「全选通过预筛」；每条显示匹配分与解析薪资标签；调用 prescreen 接口后用返回的 `passed` 批量勾选。
- `server/test/prescreen.test.js`（新）：薪资解析、城市匹配、匹配分、passed 组合。
- `web/src/api.ts` 新增 `crawl.prescreen`。

## 6. 风险与注意事项

- **interview 链的历史回溯**：`interview_history.md` 沿 parent 链回溯，链过长（>10 轮）时提示词体积增大，`max_rounds` 默认 8 兜底；SQLite 递归取父任务用 while 循环即可。
- **matches 回归**：新增 `mode='interview'` 后若忘记排除，Compare 页会混入面试轮次，需在 M4 一并处理并加回归断言。
- **PDF 中文字体**：pdfkit 对 TTC 支持有限（PingFang.ttc 是 collection），`findCjkFont()` 需实测；若 TTC 注册失败，退路是改用 `.ttf`（如 Hiragino Sans GB.ttf 不存在时用 bundled 开源字体子集，或仅导出英文/提示安装字体）。此为本功能最大不确定性，M3 先做 PoC。
- **agent 行为不可控**：interview 提示词要靠 `AGENTS.md` + `input/interview_history.md` 约束「只输出 interview schema」，与 crawl 同策略；validateInterviewTurn 兜底判失败。
- **时间成本**：interview 每轮一次 agent 运行（30-120s/轮），对话流依赖轮询；提示 UI 当前「进行中」文案即可，无需进度百分比。
- **数据模型**：不动 tasks 表结构，全靠 `mode` + `extra_prompt` + `parent_task_id`，避免迁移。
